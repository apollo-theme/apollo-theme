# Apollo Preview and Repository Branding

## Purpose

Make Apollo immediately understandable and desirable before installation: publish a distinctive organization website, show credible app-specific previews, and give every repository a polished, consistent entry point without diluting Apollo’s own identity.

## Repository architecture

- Create public `apollo-theme/apollo-theme.github.io` and serve a no-build static site at `https://apollo-theme.github.io/`.
- Add it to the parent as top-level submodule `apollo-theme.github.io`.
- Add the existing organization profile repository `apollo-theme/.github` at `.github/organization`, preserving parent CI at `.github/workflows`.
- Keep only `.github/organization/profile/README.md`; remove the duplicate `.github/organization/README.md`.
- Update parent `CLAUDE.md`, `.gitmodules`, repository lists, and validation to distinguish 17 application submodules from the two management submodules.

## Website experience

Use Apollo’s own interface language: a crisp “night flight console” built from `#141617` canvas, `#1d2021` surfaces, warm text, gold focus traces, and exact ANSI/status colors. It must not look like a generic card dashboard.

The homepage must include:

- an immediate Apollo thesis and full palette/ANSI strip;
- live-looking, hand-authored simulations for terminal, editor, Firefox, tmux/RMUX, PowerShell, bat, and eza experiences;
- one section for each of the 17 apps with stable IDs `app-<slug>`;
- repository, installation, and latest-release links per app;
- explicit labels that previews are simulations, not screenshots;
- source-of-truth and MIT links;
- thanks to Gruvbox/SonicTerm only on this website and the parent/organization profile, never in child app repositories.

The site must work without JavaScript, remain useful at 320/768/1440px, support keyboard navigation, visible focus, reduced motion, and WCAG AA text contrast. No external runtime assets except optional Google Fonts; prefer local/system monospace stacks.

## README system

Update the parent, organization profile, website, and all 17 app READMEs with a shared visual hierarchy but app-specific content:

- centered app-first title and one-sentence Apollo description;
- richer badges: preview, CI, latest release, license, app/platform, and canonical palette where relevant;
- a linked preview image generated by the website repository for that app, targeting `https://apollo-theme.github.io/#app-<slug>`;
- concise install, activate, uninstall, visual-check, and development sections using existing verified commands;
- no ancestry/lineage copy in child READMEs or child `CLAUDE.md` files; forbid the phrases `Gruvbox`, `Base16`, `SonicTerm-modified`, `based on SonicTerm`, and `derived from SonicTerm`. The `sonicterm-apollo-theme` child must still name the SonicTerm application and its real paths/commands; all children otherwise describe the palette simply as Apollo;
- preserve critical compatibility facts such as Firefox’s GUID and unsigned GitHub archive status.

The website owns generated SVG preview images under `previews/<slug>.svg`. Child READMEs embed their raw website-repository URLs so GitHub renders them reliably.

## Organization presentation

- Set the organization description exactly to `Yet, just another color theme.`
- Set the organization website to `https://apollo-theme.github.io/`.
- Rewrite `profile/README.md` as the polished organization landing summary and link to the website.
- Add repository-specific topics to every app repository: app slug/name plus `apollo-theme`, `color-theme`, and relevant ecosystem terms. Remove `gruvbox` from child topics and prose. Parent/website/profile repositories may retain lineage topics/copy.
- Update each repository description to app-first wording such as `Firefox Apollo Theme.`

## Validation and acceptance

- Website HTML/CSS/SVG passes local structural checks; all 17 IDs and preview SVGs exist and links resolve.
- Browser-test the deployed Pages site at desktop, tablet, and mobile widths; inspect console, keyboard focus, reduced-motion behavior, deep links, and all app sections.
- README validation ensures every app has the correct preview URL, required badges, app-specific title, and none of the forbidden lineage phrases. A separate allowlist permits the standalone word `SonicTerm` only where it identifies the target application, repository, path, or command in `sonicterm-apollo-theme`.
- Existing generator, native, package, and CI gates remain green in all children.
- A simulated `core.autocrlf=true` recursive clone remains deterministic.
- Child commits are pushed before parent gitlinks. Website and organization profile are independently clean and deployable.
- Do not publish to AMO or application marketplaces.

## Non-goals

- No real application screenshots in this pass; simulated previews avoid misleading platform claims.
- No JavaScript framework, package manager, analytics, tracking, backend, or custom domain.
- Do not delete `demo-repository` or rewrite historical releases.
